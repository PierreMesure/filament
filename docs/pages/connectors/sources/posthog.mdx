The PostHog source reads data from one project. It is **beta** and uses an
[HTTP manifest](/pages/connectors/building-a-connector/http-manifests).

## Configuration

| Field | Scope | Default | Description |
|---|---|---|---|
| `api_key` | Connection | | Required. Personal API key with read access to the selected resources. |
| `project_id` | Connection | | Required. Project ID from your PostHog settings or app URL. |
| `host` | Connection | `https://us.posthog.com` | US Cloud, `https://eu.posthog.com`, or your self-hosted app origin. |
| `session_recordings_start_date` | Pipeline | | Set an ISO 8601 timestamp before syncing session recordings, such as `2024-01-01T00:00:00Z`. Only retained recordings from this date are read. |

Create a [personal API key](https://posthog.com/docs/api/personal-api-keys) with
access to your project and the scopes below. Use the app host, not an ingestion
host such as `us.i.posthog.com`. Connection tests require `person:read`.

Dashboards, experiments, and notebooks fetch detail records. Child resources
fetch their required parents automatically. Nested data stays JSON; `raw`
preserves additional returned fields.

## Modes

All resources support **full reads**. Full replace reflects records absent from
the current API result; full upsert refreshes returned rows without removing
missing ones. Full reads remain the default for the 13-resource selection.

These resources also support **incremental upsert**:

| Resource | Cursor and behavior |
|---|---|
| `insights` | `last_modified_at` through `date_from`. Tracks name, description, and query edits. Tags, favorites, associations, and view/refresh metadata need periodic full reads. |
| `session_recordings` | `start_time` through `date_from`, with a 24-hour lookback for ongoing sessions. Older uploads and later metadata changes need full reads. Increase the lookback for longer delivery delays. |

Insights overlap by one second because their filter uses a strict `>` comparison. Pipeline cursor settings can increase the lookback. Select only
incremental-capable resources in an incremental pipeline; use a full-read pipeline
for the others. Notebooks use full reads and retain complete content from their
detail endpoints. Incremental reads do not propagate deletions.

## Behavior

- Pagination is automatic. Replay's `after` is a page cursor, separate from its
  timestamp filter. Child reads restart their parent traversal after interruption.
- Requests are paced at 0.3 per second with a 120-second timeout. PostHog shares
  [API limits](https://posthog.com/docs/api) with other callers.
- Results depend on permissions, product access, API version, and retention.
  Missing access produces an error.
- `survey_responses` includes submitted answers and archived responses within
  the API's survey lifetime and retention window. `surveys` contains definitions.
- Dashboards read cached tile data without requesting fresh calculations.
  Insights and experiments do not calculate fresh results. Replay resources
  contain metadata, not media; export resources contain job metadata, not files.
- This is project data coverage, not every API operation. Events remain excluded.
  Organization administration, credential APIs, arbitrary query execution,
  binary downloads, and endpoint-specific activity/sharing histories are not
  included. `llm_prompts` reads latest prompts; `hog_functions` reads list
  definitions. Alert definitions do not enumerate the full check history.

The date filters follow PostHog's implementations for
[insights](https://github.com/PostHog/posthog/blob/master/products/product_analytics/backend/presentation/insight.py)
and [replay](https://github.com/PostHog/posthog/blob/master/posthog/session_recordings/queries/session_recording_list_from_query.py).
