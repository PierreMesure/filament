The PostHog source reads data from one project. It is **beta** and uses an
[HTTP manifest](/pages/connectors/building-a-connector/http-manifests).

## Configuration

| Field | Scope | Default | Description |
|---|---|---|---|
| `api_key` | Connection | | Required. Personal API key with read access to the selected resources. |
| `project_id` | Connection | | Required. Project ID from your PostHog settings or app URL. |
| `host` | Connection | `https://us.posthog.com` | US Cloud, `https://eu.posthog.com`, or your self-hosted app origin. |
| `session_recordings_start_date` | Pipeline | | Set an ISO 8601 timestamp before syncing session recordings, such as `2024-01-01T00:00:00Z`. Only retained recordings from this date are read. |

Create a [personal API key](https://posthog.com/docs/api/personal-api-keys) with
access to your project and the scopes below. Use the app host, not an ingestion
host such as `us.i.posthog.com`. Connection tests require `person:read`.

## Resources

These 13 resources are enabled by default. You can deselect any you do not need.

| Resource | Data | Read scope |
|---|---|---|
| `actions` | Action definitions and matching steps. | `action:read` |
| `annotations` | Annotations and dashboard/insight references. | `annotation:read` |
| `cohort_members` | Current cohort membership and person properties. | `cohort:read`, `person:read` |
| `cohorts` | Cohort definitions, filters, and counts. | `cohort:read` |
| `dashboards` | Dashboard metadata, tiles, layouts, filters, and variables. | `dashboard:read` |
| `experiments` | Non-archived experiments, linked flags, and metric definitions. | `experiment:read` |
| `feature_flags` | Non-archived flags and targeting rules. | `feature_flag:read` |
| `groups` | Group profiles and properties across all group types. | `group:read` |
| `insights` | Saved analytics definitions and metadata. | `insight:read` |
| `notebooks` | Notebook content, text, variables, and metadata. | `notebook:read` |
| `persons` | Person profiles, distinct IDs, and properties. | `person:read` |
| `session_recordings` | Replay metadata from your configured start date. | `session_recording:read` |
| `surveys` | Survey definitions, questions, and targeting. | `survey:read` |

Optional resources are disabled by default. They cover activity logs, alerts,
archived experiments and flags, dashboard templates, datasets and version history,
early-access features, error tracking, evaluations, event/property definitions,
export jobs and history, group types, Hog functions, LLM configuration and reviews,
replay playlists, saved endpoints and versions, subscriptions and deliveries, and
survey responses. The events API is excluded.

Grant the read scopes required by the optional resources you select, as listed in
the [PostHog API reference](https://posthog.com/docs/api). Survey responses require
both `survey:read` and `query:read`. Resources ending in `_archived` read archived
catalogs; their history resources follow the same catalog.

Dashboards, experiments, and notebooks fetch detail records. Child resources
fetch their required parents automatically. Nested data stays JSON; `raw`
preserves additional returned fields.

## Modes

All resources support **full reads**. Full replace reflects removals from the
API result; full upsert refreshes returned rows without deleting missing ones.
Notebooks use full reads and include complete content.

`insights` also supports incremental upsert using `last_modified_at`, with a
one-second lookback. It tracks name, description, and query edits. Tags,
favorites, associations, and view/refresh metadata need periodic full reads.

`session_recordings` also supports incremental upsert using `start_time`, with a
24-hour lookback for ongoing sessions. Older uploads and later metadata changes
need full reads. You can increase the lookback in pipeline cursor settings.

Select only insights and/or session recordings in an incremental pipeline. Use
full reads for the other resources. Incremental reads do not propagate deletions.

## Behavior

- Pagination is automatic. Replay's `after` is a page cursor, separate from its
  timestamp filter. Child reads restart their parent traversal after interruption.
- Requests are paced at 0.3 per second with a 120-second timeout. PostHog shares
  [API limits](https://posthog.com/docs/api) with other callers.
- Results depend on permissions, product access, API version, and retention.
  Missing access produces an error.
- `survey_responses` includes submitted answers and archived responses within
  the API's survey lifetime and retention window. `surveys` contains definitions.
- Dashboards read cached tile data without requesting fresh calculations.
  Insights and experiments do not calculate fresh results. Replay resources
  contain metadata, not media; export resources contain job metadata, not files.
- This is project data coverage, not every API operation. Events remain excluded.
  Organization administration, credential APIs, arbitrary query execution,
  binary downloads, and endpoint-specific activity/sharing histories are not
  included. `llm_prompts` reads latest prompts; `hog_functions` reads list
  definitions. Alert definitions do not enumerate the full check history.
